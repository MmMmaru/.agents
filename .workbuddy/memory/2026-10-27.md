# 2026-10-27

### 22:45 核查 hugohe3/ppt-master 的底层实现

用户问：该 skill 底层是否基于 python-pptx。结论：**不是简单的"基于 python-pptx"，而是自写 OOXML**。

**证据（clone 后逐项核实）**
- 仓库规模：321 个 .py / 205,295 行 Python；12,193 个 .svg（其中 templates 下 12,167 个）
- `requirements.txt` 确实列 `python-pptx>=0.6.21`，注释定位为"SVG 转 PPTX 工具"用
- 全仓仅 3 个生产文件 `from pptx import`：`svg_to_pptx/pptx_package/builder.py`、`template_preview_pptx.py`、`source_to_md/ppt_to_md.py`（后者是读 PPT→Markdown，与生成无关）
- builder.py 仅两处真实调用：L7235 `Presentation()` 建空白 + add_slide(blank_layout)；L6507 `Presentation(source_template)` 只读尺寸/版式校验
- L7248 `zf.extractall(extract_dir)` 解压 → L8632 `zipfile.ZipFile(...,'w',ZIP_DEFLATED)` 重打包 —— 解包改 XML 再压回
- 真正生成形状：`svg_to_pptx/drawingml/elements.py`（5701 行，xml.etree 手拼 `<a:*>`）；`native_objects/chart_xml.py`（自称 "Classic native chart XML emitters"）、`table.py` 同为 ET 手写
- python-pptx 覆盖不了、需自研的部分：`pptx_animations.py` 3995 行、`pptx_transitions.py` 3204 行、`pptx_embedded_fonts.py` 368 行、skia-pathops 布尔运算、uharfbuzz 文字轮廓、chartEx
- 作者自述 `docs/zh/roadmap.md:146`：「如果只是固定位置替换 Excel 数据到 PPT 模板，直接让 AI 写几行 python-pptx 即可」

**真正的底层原理**：SVG 作中间语言。LLM 手写 SVG（训练数据多、浏览器可预览、结构简单），再由确定性编译器做 SVG→DrawingML 几何映射。LLM 只管画得出来，编译器管转得正确。

**对选型的提示**
- 依赖偏重：python-pptx + lxml + skia-pathops + uharfbuzz + PyMuPDF + edge-tts 等
- **PyMuPDF 是 AGPL-3.0**，商用或再分发需评估（作者已在 requirements 标注）
- 优势：产物为真原生形状/图表/表格，可在 PowerPoint 内逐元素编辑
