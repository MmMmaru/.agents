# 学术 PPT 制作原则

本 skill 规定"做成什么样"和"怎么验收"。具体的 SVG→PPTX 转换由 ppt-master skill（`~/.agents/skills/ppt-master`）完成，需要时读它的 `SKILL.md` 与 `references/`。

**参考样例**：`references/APMC2026_Oral_example.pptx` 是按本 skill 做出、并经用户多轮手改确认的 20 页会议报告。它包含多栏背景页、方法页、结果图阵页、MATLAB 格式扫描图、总结页，以及逐页英文讲稿备注。动手前先看 `references/README.md`，了解它体现了哪些规则。

## 一、内容原则（硬性）

1. **不出现代码**：不出现函数名、变量名、配置项、代码片段（如 `dispatch_key="CUDA"`、`solve_tril`、`gate_up_proj`）。改写为功能描述（"矩阵求逆""两路矩阵投影"）。
2. **不出现未解释的概念**：每个概念要么在前面页面解释过，要么是听众公认的常识。反例："Attention 融合 OFF"——没人知道指什么。
3. **不堆解释性小字**：页面上只放关键词、短句和关键数字；成段的解释、推导和口播内容写进演讲者备注。允许的小号文字只有“引用”一个层级，且全篇统一（见第二节字号层级）。
4. **少字多图，但信息密度要够**：每页以图为主体（结构图、仿真/实测图、流程图、拓扑图），配 1–3 行短文字和关键数字。不要“一图一页”“一句话一页”：同一主题的相关内容合并到一页的多个分栏，例如单元级 + 阵列级结果、S 参数 + 计算效率、方法演进的三篇代表工作并列。合并后每栏仍要有图、有结论、有数字。页面只服务一个主题，不把不相关内容塞进同一页。
5. **原理用图和动画表达**：优先用流程图、时间轴、前后对比图和分步动画。论文里已有的图优先复用（裁掉图号和图注），缺的示意图再按论文数据重画。
6. **数据真实可追溯**：数字只取自论文终稿、用户提供的原 PPT、文档或实验记录，不编造、不估算。**论文终稿是数据权威**：用当前代码、权重或数据集重新计算时，先用论文中的指标核对；对不上时以论文为准，并在备注或交付说明中写明哪些数字是新算的、用什么数据/权重算的。拿不准时问用户。
7. **结论精简**：结论区最多一条主结论加一条补充，不写长段落。
8. **每个文字块最多两行**：优先一行，硬上限为实际渲染后的两行，包含自动换行；标题、正文、图注、引用、模块标签均适用。禁止三行及以上的段落；不得拆成多个紧邻文本框来绕过限制，同一语义段落合并计算。超过两行时必须精简、改为图示或调整分栏，详细解释放入备注，**禁止缩字塞入**。此限制针对每个独立文字块，不是要求整页只能有两行文字；分栏内可以有多条各自独立的短条目。
9. **禁止编造文献或擅自增删作者**：论文标题、完整作者及顺序、期刊/会议、年份、DOI 必须依据已打开核对的论文原文或出版方正式记录填写。严禁凭主题相似、同校、同课题组、惯常合作关系、姓名缩写或模型记忆，把导师、用户或其他人补进作者名单；也不得拼接不同论文的标题、作者、年份和图片。原 PPT、生成脚本、旧大纲、AI 输出中的引用都可能有错，不能因已经存在就认定已核实。
10. **演讲者备注**：用户常把修改要求写在原 PPT 的备注（“注释”）里，开工前逐页读出。修改完成后，把这些指令备注替换为与页面一致的讲稿（汇报语言，英文会议用英文），不要把修改指令留在交付文件里。

### 文献与图片核验（硬性）

- **先核验再引用**：逐条核对原始文献，保留可追溯记录：原文路径或出版方链接/DOI、准确标题、完整作者及顺序；引用图片时再记录图号、页码及使用的幻灯片。不能仅凭搜索摘要或另一篇论文的参考文献转抄作者。
- **作者身份不能推断**：只有原文作者名单确实包含该人，且身份已核对，才可称为其本人或所在团队的工作。严禁把 `JZH` 等项目内部简称自动展开为作者，或把 `Z. H. Jiang`、`W. Hong` 等姓名自动加入相关领域论文。
- **图片与引用必须对应**：确认图片确实出自所引论文，引用紧邻图片；重绘应标明依据的原图。不能用另一篇论文的图配当前论文的作者、题名，也不能把他人图片归为自己的研究成果。
- **实物照片**：用户要“实物设备图”时，从开放获取全文取原图：arXiv、机构仓储（如 research.chalmers.se 收录的 MDPI 论文）、Europe PMC。用 pymupdf `extract_image` 取原始分辨率，按卡片比例裁切。IEEE/MDPI 直链常被拦截。找不到对应设备的照片就保留原图并告诉用户，不能拿无关或周期阵列的设备照片充数。
- **查不到就不使用**：核验不完整时，在工作底稿标注“待核实”并说明缺失证据；正式交付的 PPT 不得保留未经核实的引用、作者归属或研究归属。可先完成其他页面，必要时向用户索取原文，禁止补造信息填满版面。

写完每页自查：念给一个没看过项目的评委听，每个词他能懂吗？这一页有没有图、有没有可以带走的数字？

## 二、视觉风格

**默认采用纯黑白学术风**：白底、黑字、黑色线条，不再使用蓝白配色、灰底、灰色小字或彩色强调。修改现有 PPT 时沿用其版式、字体、logo、页脚和页面尺寸；用户明确要求保留原配色或保持原样时，遵循该次要求。不要因配色规范擅自扩展本次修改的页面范围。

页面层级靠字号、粗细、线型和留白区分，**不用颜色深浅弱化信息**。不要卡通、扁平插画、阴影和渐变。

| 用途 | 颜色 |
|------|------|
| 页面背景 / 面板底色 | 纯白 `#FFFFFF` |
| 标题、正文、副标题、图注、引用、页码 | 纯黑 `#000000` |
| 边框、分隔线、箭头、自己绘制的图形与曲线 | 纯黑 `#000000`，通过线型、线宽、标记区分 |
| 强调区域 | 白底黑框，或黑底白字；不用浅灰、浅蓝和彩色底条 |

- **不要灰色小字**：补充说明、来源和页脚同样使用纯黑，不降低透明度；正文不低于 18 pt，引用不低于 14 pt，放不下时精简或移到备注。
- **链接也用黑色**：需要提示可点击时使用下划线；原生 PowerPoint 超链接不得被主题自动改回蓝色，导出后实际检查。
- **原始图像保真**：论文原图、实物照片和官方 logo 默认保留原色，黑白规范用于自己编排的页面与自绘内容；用户明确要求图片也黑白化时再转换，不擅自改变图中数据的颜色编码。

### 字号层级（全篇一致，不硬编码具体数值）

- **按角色定字号，而不是全篇一个数**：开工前先定一张字号表，至少包含：页面标题、副标题、分栏标题、正文（含数值卡）、引用。全篇同一角色用同一字号，**每页的标题和正文字号一致**；层级之间靠字号、加粗、线型和留白区分，不靠彩色或灰度。
- **具体数值由模板和信息密度决定**：修改现有 PPT 时沿用原模板的标题字号，再按内容密度选正文字号。参考：16:9（13⅓×7½ 英寸）多分栏学术页常用标题 36 pt / 副标题 26 pt / 分栏标题 20 pt / 正文 18 pt / 引用 14 pt。正文不低于 18 pt，引用不低于 14 pt。字体沿用模板（如标题 Segoe UI Black、正文 Times New Roman）；新建中文 PPT 默认微软雅黑。
- **放不下就改内容，不缩字**：某页文字放不下时，精简措辞、调整分栏宽度或移动标签，不能单独给这一页换小字号，也不能开启自动缩小字体。原模板中个别页字号不一致（如副标题 23 pt）时，统一到字号表并缩短措辞。
- **字号单位不能混用**：字号表写最终 PowerPoint 的 pt。SVG 画布 1280×720 对应 13⅓×7½ 英寸，按 96 dpi 换算 `font-size(px) = pt × 4/3`（18 pt = 24 px，20 pt = 26.67 px，36 pt = 48 px）。1920×1080 只用于截图验收。编辑现有文件保留原页面尺寸，按其物理尺寸换算并核对最终字号。
- 公式用原生 Office Math，字号与正文层级一致；官方 logo 内的原始字形不重绘。

### 版式

- 多分栏布局（2–4 栏）**作为整体水平居中**，栏宽按内容分配，不留右侧大片空白；同类分栏的标题条、边框、间距一致。
- 图片中的关键标签要在投影下可读；原图文字过小时，放大、裁切关键区域或重绘。论文正文、原图长图注、子图编号外的无关小字从截图中裁掉，裁切边缘不能留下半截文字或线条。
- 自己生成的图（matplotlib 等）用与正文同族的字体，轴标签不要旋转成难认的样子（如竖排的 `v` 看起来像 `>`）。
- 前后对比用“原方案 / 改进方案”等明确标签，配合黑色实线、虚线或不同标记区分，不用红绿配色。
- 面板用黑色细边框、黑色标题线或留白分区，不用彩色标题条、灰色底块、阴影和渐变。

## 三、技术路线（必须遵守）

**最终交付物是文字和图形都可编辑的原生 PPTX。**

禁止：
- Chrome/Playwright 截图后贴图进 PPT
- GIF、视频嵌入，手写 `<p:timing>` XML
- python-pptx `add_picture` 整页贴图

遇到工具问题时先排查（路径、参数、校验报错），**不许自行降级成截图方案**。确实走不通，停下来问用户。

### 路线 A：新建 PPT

```
<project>/
├── svg_output/       # 每页一个 SVG，按 01_cover.svg、02_xxx.svg 编号
├── assets/           # logo、图片，SVG 里用相对路径 ../assets/... 引用
├── animations.json   # 原生动画配置
├── exports/          # 导出的 PPTX
├── PPT.md            # 本次项目的逐页要求（用户提供或整理）
└── PROGRESS.md
```

在 `.gitignore` 里忽略 `backup/`（导出工具自动生成的快照）。

### 路线 B：修改现有 PPTX（Edit Native round-trip）

用 ppt-master 的 round-trip 工作区，不改原文件，产出新版本（如 `xxx_V2.pptx`）：

1. 导入：`python <ppt-master>/scripts/pptx_to_svg.py <src.pptx> -o <ws> --inheritance-mode both --roundtrip`，得到 `authoring-svg-flat/slide_NN.svg`、`images/`、`notes/`、`page_plan.json`。先把导入的 SVG 备份一份（如 `orig-svg/`）作为重建来源。
2. 用一个生成脚本从原 SVG 出发改页：保留模板元素（背景、母版组、标题、页脚、logo），删除旧内容区，再写入新分栏。页面增删和重排写在 `page_plan.json` 的 `source_slide` 顺序里；备注写在 `notes/slide_NN.md`。
3. 刷新摘要并校验：
   ```
   python <ppt-master>/scripts/svg_authoring_view.py <ws>/authoring-svg-flat --refresh-summary
   python <ppt-master>/scripts/svg_quality_checker.py <ws> --roundtrip --json
   ```
   必须 0 error。检查器按保守字宽估算，报溢出时改措辞、改锚点或加宽所在文本框/分栏，不缩字。
4. 导出：`python <ppt-master>/scripts/svg_to_pptx.py <ws> --roundtrip`。未改页原样克隆，改过的页重建；导出回执要求 `quality_gate=passed`。
5. 新增原生公式（`data-pptx-replace-with="formula"` + JSON metadata）时，若源文件没有数学对象，导出会报 `MCE prefix 'a14' has no namespace binding`：用包装脚本在调用导出 CLI 前设置 `pptx_transitions.TRANSITION_NAMESPACES["a14"] = "http://schemas.microsoft.com/office/drawing/2010/main"`。

### Canonical SVG 规则

```xml
<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 1280 720" data-pptx-canvas="1280x720"
     lang="zh-CN" data-pptx-page-role="content" font-family="Microsoft YaHei" font-size="24">
  <rect id="bg" data-pptx-role="background" x="0" y="0" width="1280" height="720" fill="#FFFFFF"/>
  <g id="title" data-pptx-bounds="80 35 1120 85">
    <text x="640" y="88" fill="#000000" font-size="48" font-weight="bold" text-anchor="middle">页面标题</text>
  </g>
  <g id="panel-left" data-pptx-bounds="30 98 600 578"> <!-- figure + short lines + metrics --> </g>
  <g id="panel-right" data-pptx-bounds="650 98 600 578"> ... </g>
</svg>
```

- 只用 inline 属性：**不用 `<style>`，不用 `class`**。下标/上标用 `<tspan baseline-shift="sub|super">`。
- 根 `<svg>` 带 `data-pptx-page-role`，取值 cover / content / ending。
- 背景、网格等静态元素标 `data-pptx-role="background|decoration"`。
- 每个可见的顶层 `<g>` 都要有 `id` 和 `data-pptx-bounds="x y w h"`。**顶层模块区域之间不能重叠超过 1px**，内容超出自身 bounds 不能超过 5%。
- 一个文字块对应一个 `<text>`，最多两行；第二行只增加一个换行 `<tspan>`。行内强调不增加行数。
- 图片裁切用嵌套 `<svg viewBox=...>` 包住 `<image>`，不要预先裁出大量中间图片。
- 生成脚本里给文字写入函数加宽度检查（用实际字体测量，超出就报错），从源头杜绝溢出。
- XML 保留字符要转义（`&amp;`），不用 HTML 实体。
- 一个顶层 `<g>` 对应一个动画单元，规划分组时就按"讲解时点击一次出现什么"来切。

### 动画

用 `animations.json` 配原生 PowerPoint 动画，key 是 SVG 文件名去掉扩展名：

```json
{
  "version": 1,
  "defaults": {
    "transition": { "effect": "fade", "duration": 0.4, "sound": null },
    "animation": { "effect": "none", "duration": 0.4, "stagger": 0.5, "trigger": "after-previous" }
  },
  "slides": {
    "05_cuda_graph": {
      "groups": {
        "before-flow": { "effects": [ { "effect": "entrance_fade", "order": 1, "trigger": "on-click", "duration": 0.4 } ] },
        "after-flow":  { "effects": [ { "effect": "entrance_wipe", "effect_options": { "direction": "right" }, "order": 2, "trigger": "on-click", "duration": 0.8 } ] },
        "metrics":     { "effects": [ { "effect": "entrance_rise_up", "order": 3, "trigger": "on-click", "duration": 0.5 } ] }
      }
    }
  }
}
```

- 讲解步骤用 `on-click`，**不要整页自动连续播放**；同一步内的附属元素可用 `after-previous`。
- 常用效果：`entrance_fade`（文字/结论）、`entrance_wipe` + direction（流程、时间轴、"变化过程"）、`entrance_ascend`（并列卡片）、`entrance_rise_up`（指标卡）。
- 封面不加动画；要求"保持原样"的页面不加动画。用户没要求动画时不额外添加。
- 查效果参数：`python <ppt-master>/scripts/pptx_animations.py --describe <effect>`。
- 列出可动画分组：`python <ppt-master>/scripts/animation_config.py list-groups <project>`。

## 四、常用页面模板

- **多栏并列页**（背景、文献综述最常用）：2–4 个黑色虚线分栏，每栏 = 黑色标题 + 一张图 + 1–2 行特点（✓/✗）+ 底部纯黑引用；页底用黑框或黑底白字给出结论或本文目标。
- **方法演进/时间轴页**：顶部年份标签串成时间轴，下方每个年份一栏代表工作（图 + 优点 + 引用），页底一条“仍存在的问题”。
- **结构 + 要点页**：左侧大图（网络结构、天线结构），右侧编号卡片拆成 Part I / Part II，每张卡 2–3 行短句；公式用原生 Office Math 放在图下方。
- **结果对比页**：仿真 vs 预测/前 vs 后的图阵（列标签在上、行标签在左），下面 2–3 张数值卡给出误差指标；必要时左侧加一栏说明对象（如被激励单元位置）。
- **原理前后对比页**：一句话核心原理横幅 → 原路径流程（黑色实线）→ 优化路径流程（黑色虚线）→ 3 条要点 → 3–4 张指标卡；两条路径有明确文字标签。
- **总结页**：左侧 2–3 行“缩略图 + 贡献 + 关键数字”，右侧展望（配图）；不写长段落。

## 五、工作流程

1. **读原始材料**：提取原 PPT 全部文字、图片、数据和**演讲者备注**（python-pptx 或 PowerPoint COM）；读论文终稿确认数字。用户给了 `PPT.md` 或备注指令就逐条遵守。出现文献、他人成果或引用图片时，先按“文献与图片核验”逐条回查原始来源。
2. **定字号表和分栏规格**：先写下各角色字号、分栏标题条高度、边距，所有页面共用。新建 PPT 先做 2–3 页样板给用户确认风格。
3. **准备图片**：优先从论文 PDF 提取原图；需要新算的数据先与论文指标核对。**耗时的仿真或计算（如 HFSS 求解、长时间训练）先问用户再跑**；快速的读取/后处理可直接做。
4. **逐页写 SVG**（路线 A）或用生成脚本改页（路线 B），写完对照第一节自查。
5. **校验**（必须 0 error，advisory warning 可保留）：路线 A 用 `svg_quality_checker.py <project> --quick-generate --canonical-authoring --stage final --json`；路线 B 用 `--roundtrip --json`。
6. **导出**：路线 A 用 `svg_to_pptx.py <project> --quick-generate`；路线 B 用 `svg_to_pptx.py <ws> --roundtrip`。导出后复制一份为有意义的文件名（如 `xxx_V2.pptx`），不要覆盖用户正打开的原文件，删除过期导出。
7. **验收**（不能只看校验通过）：
   - PowerPoint COM 打开导出文件，不能弹修复提示；有动画时逐页打印 `TimeLine.MainSequence.Count` 与 animations.json 核对。
   - **字号审计要递归进组合**：重建页的内容都在组合里，需遍历 `GroupItems` 后再按页统计 `Font.Size`、`Font.Name`、`TextRange.Lines().Count` 和 `TextFrame2.AutoSize`。核对：同一角色全篇同一字号，标题/副标题每页一致，无三行文字块，除公式外不启用自动缩字。
   - 对照核验记录复核每条引用、作者归属及配图。短引用可用首作者加 `et al.`。
   - **黑白与可读性复核**：自己编排的背景和图形只使用纯黑、纯白；所有文字（包括引用、页码和超链接）为纯黑或黑底上的纯白，无灰色小字、透明文字或自动恢复的蓝色链接。论文原图、实物照片和官方 logo 的原色不计入自绘配色检查。
   - 每页 `Slide.Export(path, "PNG", 1920, 1080)` 导出 PNG，**逐页用 Read 查看**：文字与图片/色标是否重叠，标签是否压到分栏边框，裁切边缘有无半截文字，行列标签是否对准子图，页间同类元素位置是否一致。发现问题回到生成脚本修改，重新校验、导出、截图，直到全部通过。
   - 临时 PNG 放在 `.temp/` 下，验收后删除。
8. **记录与提交**：更新 `PROGRESS.md`。论文/PPT 本身的修改按用户规则可不 commit；代码、实验脚本的修改只 `git add` 相关文件后 commit。

## 六、和用户同时在一份 PPT 上工作（硬性）

第一次交付后，用户通常会把交付文件（如 `xxx_V2.pptx`）一直开在 PowerPoint 里，自己改标题、换图、挪位置、删元素，同时继续给我提要求。规则如下：
- **用户改的是交付文件，我改的是生成工作区**：生成脚本、出图脚本、`images/`、`notes/`。
- **版面以交付文件为准。** 每次动手前先把用户的改动吸收进生成脚本，否则下次重建会把它冲掉。
- **永远不要整套重建后覆盖交付文件**，只移植改过的页。

### 工作区约定（路线 B）

```
.temp/<ws>/
├── build_v2.py          # 主生成脚本：从原 SVG 出发逐页改写，写 page_plan.json 和 notes/
├── v2_pages_*.py        # 按章节拆出的页面函数（单文件不超过 600 行）
├── make_v2_figures.py   # 出图脚本：所有结果图从数据重算，指标写入 validation/*.json
├── images/              # 生成脚本引用的图片（含从用户 PPT 里取出的图）
├── exports/             # 每次导出的完整 PPTX（带时间戳），只作移植来源
└── backup_user_V2_HHMM.pptx   # 每次写入用户文件前的备份
```

### 每次改动的固定流程

1. **检测用户改动**：
   - 看交付文件的修改时间是否晚于我上次保存。
   - 用 COM 看 `Presentation.Saved`：`-1` 表示没有未保存的修改；不是 `-1` 就停下，请用户先保存。
   - 用 python-pptx 逐页比较当前文件与上次的备份或导出。比较要递归进组合，比形状名、位置、尺寸、文字、图片 md5 和备注，并列出用户改了哪些页、哪些元素。
2. **吸收用户改动**：
   - 把用户改的标题、位置、尺寸写回生成脚本。
   - 用户换上的图片用 `shape.image.blob` 存进 `images/`，按用户摆的位置引用。
   - 用户删掉的元素从源码里删掉。
   - 用户贴的占位图可按 md5 在仓库里其他 PPT 中查出处（例如中期报告里的 MATLAB 图），据此判断用户想要的格式和数据。
3. **在生成工作区里改**：
   - 出图：`make_v2_figures.py`。
   - 生成：`build_v2.py`。
   - 刷新摘要：`svg_authoring_view.py --refresh-summary`。
   - 校验：`svg_quality_checker.py --roundtrip`，必须 0 error。
   - 导出：`export → exports/*.pptx`。
4. **备份**：每次写入前把交付文件复制为 `backup_user_V2_HHMM.pptx`。
5. **只移植改动页**：用 PowerPoint COM 连上已打开的实例。
   - 整页替换：`InsertFromFile(导出文件, i, i, i)` 把新页插到第 i 页后，再删掉旧的第 i 页。多页从后往前做；替换后核对第 i 页和相邻页的标题；最后 `Save()`。
   - 页面版式归用户、源码还没同步时，只做原位小改：用 `Shapes.AddPicture` 按用户摆的位置换图（pt = px × 0.75），或用 `NotesPage.Shapes.Placeholders(2)` 改备注。
6. **核对**：
   - 再比较一次，确认只有目标页变了（递归进组合）。
   - `Slide.Export` 导出目标页 PNG，用 Read 查看。
7. **同步并汇报**：
   - 同步备注、讲稿、`PROGRESS.md`。
   - 回复里写清楚：改了哪几页、发现并保留了用户的哪些改动、备份路径、哪些事还要用户决定。

```powershell
$app = [Runtime.InteropServices.Marshal]::GetActiveObject("PowerPoint.Application")
$p = $null; foreach ($x in $app.Presentations) { if ($x.FullName -eq $v2) { $p = $x } }
if ($null -eq $p) { $p = $app.Presentations.Open($v2, 0, 0, -1) }   # user may have closed it
if ($p.Saved -ne -1) { "UNSAVED EDITS - ask user to save"; exit 1 }
Copy-Item $v2 "$ws\backup_user_V2_$(Get-Date -Format HHmm).pptx"
foreach ($i in @(17, 3)) { $null = $p.Slides.InsertFromFile($src, $i, $i, $i); $p.Slides($i).Delete() }   # high index first
$p.Save(); $p.Slides(3).Export("$scr\s03.png", "PNG", 1600, 900)
```

### 协作中的注意点

- **用户在我改的过程中也在改**：同一轮里用户可能在我导出之后、移植之前保存了新改动（例如删掉了图上的来源标注）。每次 COM 写入前都要重做第 1 步，不能拿上一次的检测结果。
- **尊重用户的删改，但要说明后果**：用户删掉的东西不要加回去。如果涉及许可或数据口径（如 CC BY 照片必须注明来源），就提出替代做法（把来源并到引用行），由用户决定。
- **任务中途插进来的新要求**：先回应、记下来，做完当前步骤就接着做，不能遗漏（例如“卫星图也换一下”）。
- **用户中断工具调用**：停下来等用户的新指示，不要换个方式重试刚被拒绝的操作。
- **用户整页重排过的页**：用户删表、拆组、加了自己的标签和文本框之后，生成脚本已经无法复现这一页，不能再整页移植。用 COM 原位替换图片（沿用用户图片的位置和大小），只改文本框里的字，在生成脚本里注明“第 N 页用户已改，不得移植”。
- **长时间没有输出时**：用一句话说明正在做什么，再继续。

## 七、踩过的坑

- **自行降级成截图方案**：做出来的 PPT 不可编辑、没有原生动画，被用户整体打回重做。宁可停下来问。
- **全篇硬编码一个字号**：标题、正文、引用都用 32 pt 导致每页只能放一两句话，信息密度不够；改为按角色定字号、全篇一致。
- **“少字”做成“一页一图”**：内容拆得太散，评委看不到对比和数字；相关结果合并成多栏页。
- **没问就跑耗时仿真**：HFSS 求解前未征求用户同意被打断；耗时操作先说明再执行。
- **当前权重/数据集与论文不一致**：重新推理的指标和论文对不上；以论文为准，新算的数字注明来源。
- **"第一页不改"被理解成"重新设计"**：保持原样就是原 logo、原位置、原文字，不加动画。
- **术语漂移**：页面标题改成了白话，指标卡里还留着 `GEMV`、`HBM`、`kernel`。全页都要扫一遍。
- **bounds 重叠**：上下两个模块的 bounds 首尾相接时要留 ≥ 2px 间隙；标题组的 bounds 要包住副标题行。
- **色标压住图注**：图阵旁的色标和下方的长图注容易重叠；图注从图阵左边缘起排，或给色标单独留一列。
- **行标签贴边框**：图阵左侧的行标签放在留白槽中居中，离分栏边框至少 10px。
- **用户已在交付文件上手改**：按第六节的流程处理。不要整套重建覆盖；`InsertFromFile` 会带上备注，沿用同一母版。
- **结果“太好”先查算法再出图**：阵列扫描波束的轴比只有零点几 dB，看着合理，实际是 Python 把局部坐标系的单元方向图直接合成、没有逆旋转，交叉极化被过度抵消。换算法前先用闭式公式或另一套实现（如项目里的 MATLAB）交叉核对。
- **表里的数和图上的范围口径不一致**：表只取扫描方向一个点的轴比误差（0.1–0.3 dB），图却画了 ±10° 窗口，两端靠近零点，轴比的 dB 值偏差到几十 dB，用户一看就觉得误差写小了。图画到哪里，表就统计到哪里：比如都限定在 3 dB 波束内，表给这个范围内的最大误差，并在讲稿里写明口径。
- **出图前先确认分支**：仓库切到新分支后，数据读取方式（采样顺序、频点表）和合成函数都可能已经变了，旧数据集会被读错，算出来的是乱码。出图脚本里加分支或特征检查，旧数据用单独的 worktree（如 `../paper`）运行。
- **切面曲线不够平滑**：不要对 dB 网格做 spline，零点附近会振荡，轴比甚至会出现负值。应该把单元方向图插值到细分的切面上，再精确叠加阵因子。
- **复现用户的 MATLAB 图**：用户的占位图常是从 MATLAB 复制来的 EMF/WMF。PIL 可以读出来看。保留原始数据、曲线对应关系、图例和坐标范围；按当前黑白规范重绘时，用黑色实线 / 虚线及标记区分仿真与预测，多组曲线用不同线型和标记组合，不用灰色弱化预测。用户明确要求原图原样时保留原样；数据口径要在讲稿附录里写明。
- **round-trip 新增页**：复制最接近的源页 SVG，另存为按内容命名的文件（如 `bg_applications.svg`），在 `page_plan.json` 写 `{"source_slide": N, "svg": "bg_applications.svg"}`，备注写在 `notes/bg_applications.md`；移植进用户文件时用 `InsertFromFile(新文件, 插入位置, 起页, 止页)` 一次插入连续多页，从后往前操作，序号不乱。
- **面板之间的箭头被盖住**：箭头必须在所有面板画完之后再画，否则后一个面板的底色会盖住箭头头部。
- **容量检查比字形宽度更严**：`svg_quality_checker` 按约 9.5 px/字符（14 pt 斜体引用）估宽，窄栏里的引用行要按“栏宽 ÷ 9.5”控制字符数；超了就加宽栏或减少引用条数，不要缩小字号。
- **背景/应用页配图**：优先用 arXiv（看 CC BY 许可）和机构仓储全文中的原图，图旁写作者、刊物、年份；Wiley、MDPI 等出版社页面常拒绝脚本下载，不要反复重试。
- **round-trip 改字没生效**：导入的文字可能直接在 `<text>` 上而不在 `<tspan>` 里，替换时两种都要匹配；还会带上原文本框的窄宽度和 `font-style="italic"` 等属性，替换后同步加宽文本框、去掉多余样式。
- **图表数字压住标题**：柱子顶部数值标签和图表副标题容易撞在一起，导出 PNG 后一定要看。
- **WSL 路径**：项目在 `\\wsl.localhost\...` 时，Git Bash 的 `cd` 不可用，改用 PowerShell 或 `git -C`。Windows Python 不认 `/c/...` 路径，用 `cygpath -m` 转换。
